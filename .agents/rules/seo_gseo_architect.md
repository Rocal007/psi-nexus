## II. Generative Search Engine Optimization (GSEO / GEO) Protokoll

Generative AI-Engines (SearchGPT, Perplexity, Google Gemini / AI Overviews) indizieren und zitieren Inhalte fundamental anders als traditionelle Keyword-Suchmaschinen. Der GSEO-Architekt setzt folgende Kernprinzipien durch:

```
+-------------------------------------------------------------------------+
|                    GSEO / GEO Retrieval Pipeline                        |
+-------------------------------------------------------------------------+
| 1. High Information Gain & Unique Calculation Data (Zero Generic AI-Fluff)|
| 2. Direct AI-Quotability (Stand-alone Definitive Statements)            |
| 3. Entity Graph Linking & Structured Schema.org Triples (JSON-LD)       |
| 4. Semantic Hierarchy & Fast LLM Chunking (H1 -> H2 -> Clear Bullets)  |
| 5. Machine-Readable Manifests (llms.txt, OpenGraph, DefinedTerm)        |
+-------------------------------------------------------------------------+
```

### 1. Direct Quotability & Semantic Chunking
* **Definition-First Syntax:** Jeder Hauptabschnitt (H2/H3) beginnt mit einer präzisen, 1–2 Sätze langen Definition oder Kernaussage, die von einem LLM isoliert als Zitat/Snippet extrahiert werden kann.
* **Entitäts-Dichte statt Keyword-Stuffing:** Verwendung präziser Fachtermini, astronomischer/mathematischer Einheiten, gesetzlicher Normen und geografischer Koordinaten.
* **Q&A Atomisierung:** Häufige Fragen werden im Schema `Question` + prägnante, faktenbasierte `Answer` strukturiert.

### 2. Information Gain & E-E-A-T Anchoring
* **Zero Boilerplate:** Keine nichtssagenden Einleitungen ("In der heutigen digitalen Welt...", "Es ist wichtig zu wissen...").
* **Primärdaten & Berechnungsgrundlagen:** Nennung der mathematischen/physikalischen Modelle (z. B. VSOP87, Swiss Ephemeris DE431 Standard, Placidus-Häusersystem).
* **Urheberschaft & institutionelle Verankerung:** Vollständige Einbettung von `Author`, `Organization`, `knowsAbout`, `citation` und `EducationalApplication` im JSON-LD Schema.

### 3. Machine-Readable Knowledge Interfaces
* Bereitstellung von `llms.txt` und `llms-full.txt` Spezifikationen für KI-Webcrawler.
* Saubere Auszeichnung aller Entitäten über `sameAs` (z. B. Wikidata-Links, offizielle Register, Wikipedia).

## V. Technischer SEO & Performance Standard

1. **Semantic HTML5:**
   - Genau ein semantisches `<h1>` pro Page, hierarchisch gefolgt von `<h2>` und `<h3>`.
   - Korrekte Nutzung von `<main>`, `<nav>`, `<article>`, `<section>`, `<aside>`, `<figure>`, `<figcaption>`.
2. **Meta-Tags & OpenGraph:**
   - Einzigartige, klickstarke `<title>`-Tags (50–60 Zeichen).
   - Präzise `<meta name="description">` (130–155 Zeichen) mit inhärentem E-E-A-T Call-to-Action.
   - Vollständige OpenGraph- (`og:title`, `og:description`, `og:type`, `og:image`, `og:url`) und Twitter-Card-Metadaten.
   - Selbstreferenzierende Canonical-Tags (`<link rel="canonical" href="...">`).
3. **Core Web Vitals & Astro SSG:**
   - Zero Unused JavaScript, Inline-Critical CSS wo nötig.
   - LCP (Largest Contentful Paint) < 1.2s.
   - CLS (Cumulative Layout Shift) = 0.00.
   - INP (Interaction to Next Paint) < 50ms.
4. **Structured Data:**
   - 100% fehlerfreie Schema.org JSON-LD Validierung.
